## 🧠 What Is Ventrify?

Ventrify is a venture studio that takes a client from raw idea to fully launched digital product. By the end of each engagement, a client receives:

| # | Deliverable | Primary Tool/Method |
|---|---|---|
| 1 | MVP Digital Product (e.g. Mobile App) | Claude Code + Dev Framework |
| 2 | Marketing Website | Claude Code + CMS/Static Site |
| 3 | Design System — Figma token plugins + component specs | Claude Code → Figma Plugin API |
| 4 | Design System Documentation Site | Claude Code + Next.js |
| 5 | Research & Analysis Deck | Claude Code → Puppeteer PDF |
| 6 | Product Vision Deck | Claude Code → Puppeteer PDF |
| 7 | Marketing Strategy Deck | Claude Code → Puppeteer PDF |
| 8 | Investor Pitch Deck | Claude Code → Puppeteer PDF |
| 9 | Marketing Content & Social Media Strategy | Claude Agent |
| 10 | 1-Minute Promotional Video Script + Audio Brief | Claude Agent |

## 📋 HOW TO USE THIS FILE

When starting a new client project:
1. Place this file at the root of the project as `CLAUDE.md`
2. **Run the brief intake tool** — `node tools/intake/server.js` — to open the form in your browser, fill in the client brief, and save `brief.md` to the project root automatically
3. Fill in `/brand/brand-kit.md` with client brand assets before any design or content work begins
4. Work through each phase in order, using the Claude prompts provided
6. At each phase gate, generate the client sign-off summary and get approval before proceeding
7. After SOW sign-off, run Workstream E (Design System) alongside the other workstreams — the Figma plugins and documentation site are standard deliverables on every engagement

> **Brief intake tool** (`tools/intake/server.js`) — a zero-dependency Node.js server that serves a structured form at `localhost:3010`. Covers all 8 sections of the brief template. On submit, writes a fully-formatted `brief.md` to the project root and shows the Phase 1 prompt ready to copy into Claude Code. The form uses a neutral monochromatic palette — no client branding needed.

**Claude must always read `brief.md`, `/brand/brand-kit.md`, and all previously generated phase outputs before starting any new task.**

**DS site sync rule — non-negotiable:** Whenever a Figma component, variant, token, pattern, or icon slot changes, the corresponding DS documentation site page(s) at `/design-system/` must be updated **in the same response**. Never defer DS updates. Never ask the user if they want the site updated — just do it. One change = both places updated, always.

   - MVP (v1), v1.1 post-launch quick wins, v2 growth phase
   - Rough time estimates per phase
